# Glamget · glam on a budget

**מתכננת לוקים** לנשים לפי **סוג האירוע** ו**התקציב**. זו לא חנות: לא קונים כאן, מתכננים.
בוחרים אירוע (חתונה, ערב בחוץ, עבודה או יום-יום) ותקציב בשקלים, והאפליקציה מראה רק פריטים שמתאימים, ממוינים מהזול ליקר. מרכיבים לוק של בגד, נעליים, תיק ואקססורי, רואים בזמן אמת כמה הוא עולה וכמה נשאר מהתקציב, מקבלים הצעות להשלמת הלוק, ושומרים לוקים לפעם הבאה.

פרויקט גמר בקורס 4255, פלטפורמות מתקדמות לפיתוח ב-WEB ושימוש ב-AI.

## עמודים

| כתובת | עמוד | מה עושים בו |
|---|---|---|
| `/` | פתיחה | בוחרים אירוע (כרטיסים עם איורים) ותקציב (סרגל או סכום מדויק) |
| `/items` | קטלוג (רשימה) | פריטים שמתאימים לאירוע ולתקציב, סינון לפי סוג, חיפוש לפי שם, מיון לפי מחיר |
| `/items/:id` | פריט (פרטים) | תמונות, מחיר, תיאור קצר, כמה יעלה הלוק עם הפריט, הוספה ללוק |
| `/look` | הלוק שלי | ארבעה מקומות (בגד, נעליים, תיק, אקססורי), הצעות "השלימי את הלוק", החלפת פריט, סכום מול התקציב, שמירה |
| `/saved` | לוקים שמורים | כל הלוקים ששמרתי (ב-localStorage), פתיחה לעריכה ומחיקה |
| כל כתובת אחרת | 404 | הודעה וקישור חזרה |

## פיצ'רים מרכזיים

- **סינון לפי אירוע:** לכל אירוע יש רשימת קטגוריות שמתאימות לו. למשל לחתונה: שמלות, שמלות קיץ, נעליים, תיקים ותכשיטים.
- **תקציב בכל מקום:** הקטלוג מסתיר פריטים יקרים מהתקציב, ועמוד הפריט מראה כמה יעלה הלוק אם מוסיפים אותו.
- **השלימי את הלוק:** בכל מקום ריק בלוק מוצעים עד 3 פריטים שמתאימים לאירוע ונכנסים במה שנשאר מהתקציב.
- **החלפה:** ליד כל פריט בלוק יש חלופות מאותו סוג שנכנסות בתקציב.
- **לוקים שמורים:** שמירה עם שם. בעריכה של לוק שמור כל שינוי נשמר בו אוטומטית, ו"הלוק שלי" מתרוקן כשיוצאים מהעריכה.

## ה-API

[DummyJSON](https://dummyjson.com/docs/products): חנות לדוגמה, ציבורית וחינמית, **בלי מפתח**.

- כל המוצרים: `GET https://dummyjson.com/products?limit=0`
- מוצר אחד: `GET https://dummyjson.com/products/{id}`

משתמשים רק בקטגוריות של נשים: שמלות, שמלות קיץ (`tops`, שבה יש בפועל שמלות קצרות), נעליים, תיקים, תכשיטים, שעונים ומשקפי שמש.
המחירים מגיעים בדולרים יחד עם אחוז הנחה. האפליקציה מציגה מחיר אחד, המחיר העדכני אחרי ההנחה, בשקלים לפי שער קבוע (3.7).
אחרי שהמוצרים נטענו פעם אחת הם נשמרים בזיכרון (`api.ts`), כך ששאר העמודים לא מבקשים אותם שוב.

## איך מריצים

צריך [Node.js](https://nodejs.org) (גרסה 20 ומעלה).

```bash
npm install      # התקנה, פעם אחת
npm run dev      # הרצה. פותחים את הכתובת שמופיעה (בדרך כלל http://localhost:5173)
npm run build    # בדיקה שהפרויקט נבנה בלי שגיאות
```

> ב-Windows, אם PowerShell חוסם את `npm` (הודעה על running scripts), כותבים `npm.cmd` במקום `npm`.

## איך בודקים

```bash
npm test         # מריץ את כל הבדיקות פעם אחת
npm run test:ui  # פותח את Vitest UI בדפדפן ומראה את הבדיקות בצורה ויזואלית
```

34 בדיקות בשני קבצים:
- `src/utils/styleLogic.test.ts`, **32 בדיקות ללוגיקה:** המרת מחירים, סינון לפי אירוע, תקציב וחיפוש, מיון, הרכבת הלוק, הצעות וחלופות, חישוב התקציב, שמירה ועריכה של לוקים, וקיצור התיאור.
- `src/components/BudgetBar.test.tsx`, **2 בדיקות לרכיב** (Testing Library): מה כתוב כשהלוק בתוך התקציב, ומה כשחורגים.

## מגבלות ידועות

- **הפריטים דמיוניים:** DummyJSON היא חנות לדוגמה, ולכן יש בה כ-35 פריטי נשים בלבד, בלי מכנסיים ובלי מידות.
- **התיאורים באנגלית:** כך הם מגיעים מה-API. מוצג רק המשפט הראשון.
- **הלוקים נשמרים בדפדפן (localStorage):** כל דפדפן שומר לוקים משלו. שמירה לפי משתמש הייתה דורשת שרת והתחברות, וזה מחוץ להיקף.

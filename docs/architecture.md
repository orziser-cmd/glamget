# איך Glamget בנויה

## התמונה הגדולה

```
                    ┌──────────────── App.tsx ────────────────┐
                    │  settings    (אירוע + תקציב)             │
                    │  look        (הלוק הנוכחי)               │
                    │  savedLooks  (לוקים שמורים)              │
                    │  editingId   (איזה לוק שמור עורכים)       │
                    │  + שומר הכול ב-localStorage               │
                    └───────────────┬──────────────────────────┘
                                    │ props
     ┌──────────────┬───────────────┼───────────────┬───────────────┐
     ▼              ▼               ▼               ▼               ▼
 HomePage      CatalogPage      ProductPage      MyLookPage    SavedLooksPage
 אירוע ותקציב  כל המוצרים       מוצר אחד         הלוק, הצעות,   לוקים שמורים
 (+ תמונות)    FilterBar        הוספה ללוק       החלפה, שמירה   פתיחה ומחיקה
               ProductCard × N                   BudgetBar
        │            │               │               │
        └────────────┴───── api.ts ──┴───────────────┘
                     (fetch + זיכרון לרשימת המוצרים)
                               │
                          DummyJSON
```

## איפה כל מידע "גר"

| מידע | איפה | למה שם |
|---|---|---|
| אירוע ותקציב | `App` (state) | הקטלוג, עמוד הפריט והלוק צריכים אותם |
| הלוק הנוכחי | `App` (state) | עמוד הפריט מוסיף אליו, עמוד הלוק מציג אותו, התפריט סופר אותו |
| לוקים שמורים ו-`editingId` | `App` (state) | עמוד הלוק שומר ועורך, עמוד השמורים מציג |
| הבחירות במסך הפתיחה (לפני הלחיצה) | `HomePage` (state) | נשלחות ל-`App` רק כשלוחצים "לקטלוג שלי" |
| רשימת המוצרים | `api.ts` (זיכרון) + state בכל עמוד שמציג אותה | נטענת פעם אחת ומשמשת את מסך הפתיחה, הקטלוג ועמוד הלוק |
| סינון, חיפוש ומיון | `CatalogPage` (state) | רק הקטלוג צריך אותם |
| מוצר אחד | `ProductPage` (state) | רק עמוד הפריט צריך אותו |

**הכלל:** מידע נשמר ברכיב הכי נמוך שכל מי שצריך אותו נמצא מתחתיו. אם כמה עמודים צריכים אותו, הוא עולה ל-`App` ויורד לעמודים ב-props.

## הזרימה: מה קורה כשלוחצים "הוסיפי ללוק"

1. `ProductPage` קוראת לפונקציה `onAddToLook(product)` שקיבלה ב-props.
2. הפונקציה הזו היא `handleAddToLook` שנמצאת ב-`App`.
3. היא קוראת ל-`addToLook` מ-`styleLogic.ts`, שמחזירה לוק חדש. אם כבר היו נעליים, החדשות מחליפות אותן.
4. `setLook` שומר את הלוק החדש. React מצייר מחדש: המספר בתפריט עולה.
5. `useEffect` ב-`App` מזהה שהלוק השתנה ושומר אותו ב-localStorage.

## הזרימה: עריכה של לוק שמור

1. ב"שמורים" לוחצים "פתיחה לעריכה". `App` טוען את הלוק ל-`look` ושומר את המזהה שלו ב-`editingId`.
2. בכל שינוי בלוק, `useEffect` ב-`App` מעדכן את הלוק השמור (`updateSavedLook`).
3. כשיוצאים מאזור העריכה (עמוד הלוק, או הקטלוג שאליו קופצים כדי לבחור פריט), או לוחצים "סיום עריכה", `look` מתרוקן ו-`editingId` חוזר ל-null.

## למה הלוגיקה בקובץ נפרד

`styleLogic.ts` לא יודע כלום על מסכים. הוא רק מקבל מידע ומחזיר תשובה. ככה:
- קל לבדוק אותו בבדיקות, בלי דפדפן.
- הרכיבים נשארים פשוטים: הם רק מציגים.
- אם רוצים לשנות כלל (למשל מה מתאים לחתונה), משנים במקום אחד.

## שלושת המצבים של טעינה

בכל עמוד שמציג מידע מה-API יש שלושה state:
- `isLoading`: מתחיל `true`. כל עוד הוא `true`, מוצג "טוענת…".
- `error`: אם ה-fetch נכשל, נשמרת בו הודעה ומוצגת הודעת שגיאה.
- המידע עצמו (`products` / `product`): מוצג כשהטעינה הסתיימה בלי שגיאה.

בעמוד הלוק, הצעות שלא נטענו לא חוסמות את העמוד: מופיעה הודעה קטנה במקום ההצעות. במסך הפתיחה, אם התמונות לא נטענו, מופיעים רקעים צבעוניים בלי תמונה.
